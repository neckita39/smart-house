# Веб-пульт умного дома Яндекса

Локальное приложение для управления устройствами умного дома Яндекса с ноутбука:
один Go-бинарник со встроенным веб-интерфейсом.

## Требования

- Go 1.26+
- Node 20+ (только для сборки фронтенда)
- OAuth-приложение на https://oauth.yandex.ru с правами `iot:view` и `iot:control`

## Запуск

1. Скопировать `.env.example` в `.env` и вписать `YANDEX_CLIENT_ID` / `YANDEX_CLIENT_SECRET`.
2. `make build` — соберёт фронтенд и бинарник `smart-house`.
3. `./smart-house` и открыть http://127.0.0.1:8080 (порт настраивается — см. ниже).
4. При первом запуске нажать «Открыть страницу Яндекса», разрешить доступ,
   скопировать показанный код и вставить в форму. Токен сохранится в `data/token.json`.

Порт по умолчанию — 8080, задаётся переменной `PORT` в `.env`. Если 8080 занят
(например, Docker Desktop держит `*:8080` под свой nginx) — задайте `PORT` в
`.env` и открывайте именно http://127.0.0.1:PORT, а не `localhost` (на занятом
порту `localhost` может резолвиться в другой процесс и отвечать не тем).

## Сценарии через Claude

Главный способ создавать сценарии — попросить Claude Code в этом проекте:
«сделай сценарий „кино“: выключи верхний свет, подсветку на 30 %». Skill
`.claude/skills/smart-home` читает каталог устройств (`GET /api/catalog`),
собирает макрос из реальных устройств, сохраняет его через API и по просьбе
запускает. Сервер должен быть запущен (Claude запустит его сам, если нужно).

## Автоматизации

Правила «если условие — сделай действие» (освещённость, температура, влажность,
PM2.5, мощность, время, состояние устройств), которые сервер проверяет сам на
каждом опросе дома (по умолчанию раз в 10 секунд — `POLL_SECONDS`) и выполняет
без участия Claude. Реакция на изменение — до 10 секунд, поэтому для мгновенных
сценариев («свет по движению») лучше использовать родные сценарии Яндекса.

Создаются и правятся через `.claude/skills/smart-home` (раздел 5 файла
`SKILL.md`) или напрямую через API — см. `internal/server/rule_handlers.go`.
Хранятся в `data/rules.json`, журнал срабатываний — в `data/events.jsonl`
(файлы в каталоге `DATA_DIR`, по умолчанию `data`).

Чтобы держать вторую копию сервера (например, на ноутбуке разработчика) без
собственных автоматизаций — не мешать той, что уже работает на домашнем
сервере, — задайте `RULES_ENABLED=false` в `.env` этой копии.

Дизайн фичи — `docs/superpowers/specs/2026-09-08-automations-design.md`.

## Разработка

- Нужен Node 20.19+ или 22.12+ (требование Vite 7).
- Перед `go run .` нужно хотя бы раз собрать фронтенд — `make web`. Без этого
  `web/dist` пуст и сервер отдаёт 503 «UI не собран» на всех страницах, кроме API.
- `make test` — форматирование, vet и тесты Go.
- Фронтенд с горячей перезагрузкой: `go run .` в одном терминале,
  `cd web && npm run dev` в другом (Vite проксирует `/api` на `127.0.0.1:PORT` —
  берёт `PORT` из корневого `.env`, по умолчанию 8080).

## Деплой на домашний сервер

По умолчанию сервер слушает только `127.0.0.1` — недоступен из сети. Чтобы
управлять умным домом с других устройств в доме, можно установить приложение
на постоянно включённый компьютер в локальной сети (например, старый Intel
Mac) и открывать его с телефона или ноутбука.

1. `.env` на сервере: `HOST=0.0.0.0` (слушать все интерфейсы) и
   `ALLOWED_HOSTS=192.168.1.95` — IP или имя, по которому к серверу
   обращаются из сети (можно несколько через запятую).
2. На своей машине: `make build-intel` — соберёт фронтенд и кросс-скомпилирует
   бинарник под Intel Mac (`build/smart-house-darwin-amd64`, без CGO).
3. Разово скопировать `.env` на сервер: `scp .env user@192.168.1.95:smart-house/.env`.
4. `make deploy DEPLOY=user@192.168.1.95` — скопирует бинарник и файлы деплоя,
   установит и (пере)запустит launchd-агент `com.neckita39.smart-house`
   (`deploy/install.sh`, `RunAtLoad` + `KeepAlive` — переживёт перезагрузку и
   перезапустится при падении).
5. Открыть в браузере `http://192.168.1.95:PORT` (порт — из `.env` на сервере).
6. Лог сервера — `~/smart-house/smart-house.log` на сервере (`ssh user@192.168.1.95 tail -f smart-house/smart-house.log`).
7. Если порт занят — посмотреть, что слушает, на сервере: `lsof -nP -iTCP -sTCP:LISTEN`, и задать другой `PORT` в `.env`.

**Важно:** при `HOST=0.0.0.0` API доступен любому устройству в локальной сети
без дополнительной аутентификации — используйте только в доверенной домашней
сети, не пробрасывайте порт наружу.

## Ограничения

- API Яндекса не умеет создавать сценарии — вместо этого есть локальные макросы
  (`data/macros.json`), выполняемые через `devices/actions`.

# Веб-пульт умного дома Яндекса — дизайн

Дата: 2026-09-08
Статус: одобрен

## Цель

Локальное веб-приложение для управления умным домом Яндекса с ноутбука:
вкл/выкл устройств, тонкое управление (яркость, цвет, температура),
показания датчиков, запуск родных сценариев Яндекса и собственные
локальные макросы.

Работает на старом ноутбуке, поэтому приоритет — минимум ресурсов:
один Go-бинарник, без Node в рантайме.

## Ограничения и факты об API

- База: `https://api.iot.yandex.net`, авторизация Яндекс OAuth,
  scopes `iot:view` + `iot:control`.
- Ключевые endpoints:
  - `GET /v1.0/user/info` — комнаты, устройства, группы, сценарии;
  - `GET /v1.0/devices/{id}` — состояние устройства;
  - `POST /v1.0/devices/actions` — управление устройствами;
  - `POST /v1.0/scenarios/{id}/actions` — запуск сценария;
  - `POST /v1.0/groups/{id}/actions` — управление группой.
- Создавать/редактировать сценарии через API **нельзя** — только
  запускать существующие. Поэтому «создание сценариев» реализуется
  локальными макросами внутри приложения.
- API не отдаёт CORS-заголовки — браузер не может ходить в него
  напрямую, все запросы идут через Go-сервер.
- Push-уведомлений для клиентских приложений нет — состояние
  обновляется опросом.
- В ответах Яндекса есть `request_id` — логировать для разбора ошибок.

## Архитектура

Один Go-бинарник:

- HTTP-сервер на `localhost:8080` (порт настраивается);
- раздаёт React-фронтенд, вшитый через `go:embed` (билд Vite);
- проксирует запросы к `api.iot.yandex.net`, подставляя OAuth-токен;
- хранит состояние в локальных файлах в `data/` (не в git).

Браузер общается только с `localhost:8080` — same-origin, без CORS.

```
Браузер (React SPA) ── /api/* ──> Go-сервер ──> api.iot.yandex.net
                                     │
                                     ├─ data/token.json  (OAuth-токены)
                                     └─ data/macros.json (макросы)
```

## Авторизация

OAuth-приложение уже зарегистрировано на oauth.yandex.ru
(client_id/secret лежат в `.env`, в git не попадают).
В настройках приложения нужно добавить Redirect URI:
`http://localhost:8080/auth/callback`.

Поток:

1. `GET /auth/login` → redirect на
   `https://oauth.yandex.ru/authorize?response_type=code&client_id=...`.
2. Пользователь разрешает доступ, Яндекс редиректит на
   `/auth/callback?code=...`.
3. Сервер меняет код на access + refresh токены
   (`POST https://oauth.yandex.ru/token`, client_id + client_secret).
4. Токены сохраняются в `data/token.json`; сервер обновляет access-токен
   по refresh-токену до истечения срока. Повторный вход не нужен.
5. Если токен невалиден и обновить не удалось — `/api/*` отвечает 401,
   фронт показывает кнопку «Войти через Яндекс».

## Бэкенд (Go, стандартная библиотека)

Внутренний API (все ответы JSON):

| Метод | Путь | Что делает |
|---|---|---|
| GET | `/api/home` | Прокси `user/info`: комнаты, устройства, группы, сценарии |
| POST | `/api/devices/actions` | Управление устройствами (формат тела — как у Яндекса) |
| POST | `/api/scenarios/{id}/run` | Запуск родного сценария |
| GET | `/api/macros` | Список локальных макросов |
| POST | `/api/macros` | Создать макрос |
| PUT | `/api/macros/{id}` | Обновить макрос |
| DELETE | `/api/macros/{id}` | Удалить макрос |
| POST | `/api/macros/{id}/run` | Выполнить макрос через `devices/actions` |
| GET | `/auth/login`, `/auth/callback`, `GET /api/auth/status` | OAuth-поток |

Макрос: `{id, name, actions: [{device_id, capability_type, instance,
value}, ...]}` — хранится в `data/macros.json`, выполняется одним
запросом `devices/actions` (Яндекс принимает несколько устройств за раз).

Конфигурация через `.env` / переменные окружения:
`YANDEX_CLIENT_ID`, `YANDEX_CLIENT_SECRET`, `PORT` (по умолчанию 8080).

Логи: каждый запрос к Яндексу — метод, путь, статус, `request_id`.

## Фронтенд (React + Vite)

Одна страница, две вкладки:

**Дашборд** — устройства по комнатам:
- тумблер вкл/выкл (`on_off`);
- слайдеры яркости/температуры и выбор цвета (`range`, `color_setting`);
- режимы (`mode`) — выпадающий список;
- датчики (`properties`: температура, влажность, открытие и т.п.) —
  только чтение, с автообновлением.

Опрос `/api/home` раз в ~10 секунд; после действия пользователя —
немедленное обновление. Оптимистичное переключение тумблеров с откатом
при ошибке.

**Сценарии** — кнопки запуска родных сценариев Яндекса + список локальных
макросов с созданием/редактированием (выбор устройств и действий из
данных `/api/home`), запуском и удалением.

Билд Vite кладётся в каталог, который Go встраивает через `go:embed`;
в dev-режиме — Vite dev server с прокси на Go.

## Обработка ошибок

- Ошибки Яндекса транслируются в понятные сообщения UI
  (устройство офлайн, действие не поддерживается).
- 401 от Яндекса → попытка refresh → при неудаче 401 фронту и
  предложение войти заново.
- Ответ `devices/actions` разбирается по устройствам: если часть
  действий не прошла — показать, какие именно.

## Тестирование

Только Go-часть (первая версия):
- клиент Яндекс-API — через `httptest`-мок (успех, ошибка, 401);
- хранилище макросов — CRUD на временном файле;
- обновление токена — истёкший access → refresh → повтор запроса.

Фронтенд в первой версии без тестов.

## Вне рамок первой версии

- Доступ с других устройств/из интернета (только localhost).
- Создание/редактирование родных сценариев Яндекса (API не умеет).
- История показаний датчиков, графики.
- Управление группами как отдельный UI (данные есть в `/api/home`,
  кнопки — позже при желании).

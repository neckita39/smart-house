# Автоматизации — дизайн

Дата: 2026-09-08
Статус: на утверждении
Основа: `docs/superpowers/specs/2026-09-08-smart-home-web-remote-design.md`

## Зачем

Владельцу нужны не «режимы по кнопке», а автоматика: само включилось,
само выключилось. API Яндекса не позволяет создавать сценарии с
триггерами, но наш сервер уже опрашивает дом каждые 10 секунд — этого
достаточно, чтобы выполнять правила «если … → сделать …» локально, а
Claude — писать их по описанию владельца так же, как макросы.

Честное ограничение: реакция на событие — до 10 секунд (интервал опроса).
Мгновенные вещи (свет по движению) остаются родным сценариям Яндекса;
наши правила — для «медленных» и составных сигналов: освещённость,
температура, влажность, PM2.5, мощность, время суток, состояние устройств.

## Стартовый набор правил (утверждён владельцем)

| Правило | Условия (все одновременно) | Действия |
|---|---|---|
| Кабинет жарко | датчик климата (кабинет) temperature > 25; жалюзи open > 50; время 11:00–17:00 | жалюзи open = 40 |
| Кабинет остыл | temperature < 23 или время ≥ 19:00; жалюзи open < 100 | жалюзи open = 100 |
| Гостиная жарко | датчик климата (гостиная) temperature > 25; шторы open > 30; 11:00–17:00 | шторы в гостиной open = 30 |
| Гостиная остыла | temperature < 23 или ≥ 19:00; шторы open < 100 | шторы open = 100 |
| Душно в спальне (день) | датчик климата (спальня) temperature > 25.5; 08:00–22:00 | вентилятор on = true, fan_speed = medium |
| Душно в спальне (ночь) | temperature > 25.5; 22:00–08:00 | вентилятор on = true, fan_speed = low |
| Спальня остыла | temperature < 23.5; вентилятор on = true | вентилятор on = false |
| Пыль в спальне | очиститель pm2.5_density > 15 | очиститель on = true |
| Воздух чистый | pm2.5_density < 5 держится 20 минут; очиститель on = true | очиститель on = false |
| Стемнело → шторы | датчик движения (балкон) illumination < 30; 16:00–23:59 | шторы в спальне open = 0; шторы в гостиной open = 0 |
| Пасмурно → фитолампа | illumination < 200; 09:00–18:00; фитолампа on = false | фитолампа on = true |
| Светло → фитолампа выкл | illumination > 800 или время ≥ 18:00; фитолампа on = true | фитолампа on = false |
| Забытый ТВ | телевизор в гостиной on = true; 02:30–06:00 | телевизор on = false (кулдаун 120 мин) |

«или» в таблице реализуется двумя правилами с одинаковыми действиями.
Значения проверены по каталогу: `fan_speed` ∈ {low, medium, high};
`open` 0–100; PM2.5 — свойство `pm2.5_density` самого очистителя;
освещённость — свойство `illumination` датчика движения на балконе (лк).

## Модель правила

Файл `data/rules.json` (сервер — единственный писатель):

```json
{
  "id": "a1b2…", "name": "Кабинет жарко → жалюзи", "enabled": true,
  "when": [
    {"device_id": "<датчик>", "property": "temperature", "op": ">", "value": 25},
    {"device_id": "<жалюзи>", "capability": "open", "op": ">", "value": 50},
    {"time": {"after": "11:00", "before": "17:00"}}
  ],
  "for_minutes": 0,
  "cooldown_minutes": 60,
  "then": [
    {"device_id": "<жалюзи>", "type": "devices.capabilities.range", "instance": "open", "value": 40}
  ]
}
```

- Условия объединяются по «И». Виды: `property` (показание датчика:
  `state.value` свойства), `capability` (состояние умения по `instance`),
  `time` (окно по локальному времени сервера; `after > before` — окно
  через полночь). Операторы `< <= > >= == !=`; значения — число, bool,
  строка.
- `for_minutes` — условия должны непрерывно выполняться N минут
  (по умолчанию 0). `cooldown_minutes` — не срабатывать повторно раньше
  чем через N минут (по умолчанию 30).
- Срабатывание по фронту: правило выполняется, когда набор условий
  становится истинным (после `for_minutes`), и не повторяется, пока
  условия не станут ложными и снова истинными; кулдаун — дополнительно.
- Действия: элементы формата макроса `{device_id, type, instance,
  value}` и два дополнительных: `{"macro_id": "…"}` (выполнить локальный
  макрос) и `{"scenario_id": "…"}` (запустить сценарий Яндекса). Все
  действия над устройствами одного правила уходят одним запросом
  `devices/actions`.
- Валидация при сохранении: устройство и `instance` существуют в текущем
  снимке дома; `value` для `mode` — из списка режимов, для `number` — в
  `min..max`; иначе 400 с объяснением по-русски.

## Опрос на сервере

Новый пакет `internal/poller`: цикл раз в `POLL_SECONDS` (по умолчанию 10)
делает `user/info`, хранит последний сырой JSON, время и «снимок» —
`map[deviceID]` → значения свойств и умений по `instance`. Опрос идёт
только при наличии токена; после 401 останавливается до нового входа.
`GET /api/home` и `GET /api/catalog` отдают данные из снимка (заголовок
`X-Snapshot-Age` в секундах), не ходя в Яндекс на каждый запрос фронта;
если снимка ещё нет — один синхронный запрос. Действия пользователя
(`devices/actions`) после выполнения инициируют внеочередной опрос.

## Движок правил

Пакет `internal/rules`: `Store` (CRUD в `rules.json`, как у макросов),
`Engine.Tick(snapshot, now)` — вычисляет условия каждого включённого
правила, ведёт состояние (с какого момента истинно, когда последний раз
сработало) и возвращает список сработавших; исполнение действий — через
клиент Яндекса. Каждое срабатывание и каждая ошибка пишутся в
`data/events.jsonl` (`time, rule_id, rule_name, ok, details`); в памяти —
последние 500 событий для API.

## API

| Метод | Путь | Что делает |
|---|---|---|
| GET/POST | `/api/rules` | список / создать |
| PUT/DELETE | `/api/rules/{id}` | изменить (в т.ч. `enabled`) / удалить |
| POST | `/api/rules/{id}/run` | выполнить действия правила сейчас (без условий) |
| GET | `/api/rules/{id}/check` | вычислить условия сейчас: по каждому — истинно ли и текущее значение |
| GET | `/api/events?limit=100` | журнал срабатываний |

## Интерфейс

Вкладка «Автоматизации» в стиле «Плитки»: плитка правила — имя,
переключатель `enabled`, человекочитаемое описание условий и действий,
«последний раз: …», кнопка «Проверить» (показывает ✓/✗ по условиям с
текущими значениями), удаление. Ниже — журнал срабатываний. Редактора
правил в интерфейсе нет: правила создаёт Claude через API; из интерфейса
их включают, выключают, проверяют и удаляют.

## Тесты

Go: движок (фронт срабатывания, `for_minutes`, кулдаун, окно через
полночь, операторы), хранилище правил (валидация по снимку), poller
(снимок из образца `user/info`, остановка после 401), обработчики API
(CRUD, check, events). Фронт — без тестов, проверка вживую.

уведомления (Telegram и т.п.); дни недели; определение присутствия.
